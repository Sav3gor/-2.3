# Звіт із практичної роботи КП 2.8

## Тема, мета та вихідні умови

**Тема:** управління списком завдань у PWA-застосунку TaskFlow: видалення, зміна статусів, пошук, комбінована фільтрація та сортування.

**Мета:** навчитися керувати реактивним масивом у Vue 3, використовувати ref() і computed(), створювати керовані компоненти та передавати події через Emits із синхронним оновленням сторінок.

Роботу виконано в існуючому проєкті TaskFlow на Vue 3, Framework7 і Vite. Попередня робота забезпечувала створення та редагування завдань, валідацію, категорії, попередній перегляд, статистику й базову фільтрацію. Новий проєкт не створювався. main.js, App.vue, routes.js, AppTabbar.vue, StatusBadge.vue, PriorityBadge.vue та початкові дані не змінено.

Після виконання користувач може шукати за назвою й описом, поєднувати умови, сортувати записи, змінювати статус і пріоритет, редагувати, видаляти з підтвердженням та скидати умови пошуку. Початкові десять записів збережено. Дані залишаються лише в пам’яті; Pinia, localStorage та IndexedDB не додаються.

## Теоретичні відомості

**ref()** зберігає реактивні значення пошуку, фільтрів, сортування та стану відкритої форми. **computed()** повертає похідний список і відсоток виконаних у вибірці, автоматично оновлюючи їх при зміні залежностей.

**filter()** створює новий масив усіх записів, що задовольняють умову. **sort()** змінює масив на місці, тому застосовується тільки до результату filter(), а не до taskState.tasks. **findIndex()** повертає індекс завдання за умовою; **splice(index, 1)** видаляє один запис і запускає реактивне оновлення Vue.

Пошук прибирає крайні пробіли, переводить текст у нижній регістр з локаллю uk-UA та перевіряє спільний рядок назви й опису. Умови тексту, статусу, пріоритету й швидкого фільтра об’єднані логічним AND.

## Керовані компоненти та події

TaskListControls отримує Props search, status, priority, sort та incomplete. Компонент не має власного масиву завдань і не змінює Props. Поля генерують update:search, update:status, update:priority, update:sort та update:incomplete. Кнопка скидання генерує reset.

```vue
<TaskListControls v-model:search="searchQuery"
  v-model:status="selectedStatus"
  v-model:priority="selectedPriority"
  v-model:sort="sortOrder"
  v-model:incomplete="onlyIncomplete"
  @reset="resetFilters" />
```

TaskCard передає status-change, priority-change, edit, delete та task-select. Батьківська TasksPage викликає функції сховища. Редагування й видалення доступні у вкладці завдань через editable=true; головна зберігає попередній вигляд карток.

## Пошук, фільтрація та сортування

```js
const term = searchQuery.value.trim().toLocaleLowerCase('uk-UA')
const result = taskState.tasks.filter(task => (
  (selectedStatus.value === 'all' || task.status === selectedStatus.value) &&
  (selectedPriority.value === 'all' || task.priority === selectedPriority.value) &&
  (!onlyIncomplete.value || task.status !== 'done') &&
  `${task.title} ${task.description ?? ''}`
    .toLocaleLowerCase('uk-UA').includes(term)
))
```

Режими сортування: спочатку нові за ID; назва А–Я з localeCompare('uk-UA'); високий або низький пріоритет першим; найближчий або найдальший термін першим; статуси «У роботі → Заплановано → Виконано»; початковий порядок за ID. Для рівних значень застосовано ID як додатковий критерій.

Завдання без терміну завжди розташовуються після датованих в обох напрямках сортування. Це забезпечено окремою перевіркою відсутності дати перед її порівнянням. Сортується тільки окремий масив, тому спільний порядок даних не змінюється.

Скидання очищує текст, повертає статус і пріоритет на «Усі», вимикає швидкий фільтр і встановлює «Спочатку нові». При збереженні форми умови теж скидаються, щоб створений або відредагований запис було видно.

## Видалення та реактивність

```js
export function deleteTask(id) {
  const index = taskState.tasks.findIndex(task => task.id === Number(id))
  if (index === -1) return false
  taskState.tasks.splice(index, 1)
  return true
}
```

Обробник handleDelete() знаходить запис і викликає window.confirm() з назвою завдання. За скасування сховище не змінюється. Після підтвердження викликається deleteTask(); якщо видалено редагований запис, форма закривається; якщо вибраний — панель вибору прибирається. Виводиться повідомлення про результат.

TasksPage та HomePage використовують один reactive taskState. Після видалення або зміни статусу автоматично оновлюються картки, лічильники, статистика й відсоток виконання. Відсутній ID повертає false та не видаляє інші записи.

## Виконані додаткові завдання

1. «Тільки невиконані» поєднується з текстом, статусом і пріоритетом; активний стан передано через aria-pressed.
2. Додано сортування за статусом: «У роботі → Заплановано → Виконано».
3. Біля кількості знайдених показується відсоток виконаних серед поточної вибірки; для нульової вибірки — 0%.
4. «Очистити пошук» відображається лише за непорожнього рядка та очищує тільки текст, залишаючи інші умови.
5. Після видалення всіх записів показується окреме пояснення «Список завдань порожній» та кнопка створення першого завдання. Для нульового результату фільтрації є інше повідомлення і скидання умов.
6. Додано сортування термінів у зворотному порядку; записи без дати залишаються наприкінці.

З попередніх робіт збережено категорії, унікальність назви нового завдання, лічильники символів, очищення форми, preview, доступні повідомлення, TaskCounter і task-select. Заповнена нова дата не може бути минулою; під час редагування дозволено залишити попередній термін.

## Контрольні запитання

1. **Призначення ref().** Створює реактивне значення для пошуку, обраного фільтра, сортування та іншого локального стану.
2. **Коли computed() замість функції?** Для похідного реактивного значення, яке потрібно кешувати й автоматично оновлювати при зміні залежностей.
3. **filter() і find().** filter() повертає масив усіх відповідних записів; find() — перший відповідний запис або undefined.
4. **Чому не сортуємо спільний масив?** sort() змінює його на місці й впливає на інші компоненти; сортуємо копію після filter().
5. **Пошук за назвою й описом.** Об’єднуємо їх у рядок, нормалізуємо регістр через toLocaleLowerCase('uk-UA') і перевіряємо includes(term).
6. **Поєднання фільтрів.** Умови пошуку, статусу, пріоритету та швидкого фільтра поєднуються логічним AND.
7. **Навіщо localeCompare()?** Для порівняння назв з урахуванням української абетки й правил локалі.
8. **Завдання без терміну.** Залишаються внизу в обох напрямках сортування дат.
9. **Роль defineEmits().** Оголошує події дочірнього компонента та повертає функцію для повідомлення батьківського компонента про дії.
10. **Чому видалення обробляє сторінка?** Сторінка керує спільним станом, підтвердженням, формою й панеллю вибору; картка лише повідомляє ID.
11. **findIndex() і indexOf().** findIndex() приймає функцію-предикат, наприклад перевірку id; indexOf() шукає саме передане значення, для об’єктів — те саме посилання.
12. **Як splice() впливає на відображення?** Змінює реактивний масив, після чого Vue оновлює залежні списки та computed-показники.
13. **Для чого :key?** Надає кожній картці стабільну ідентичність за ID, потрібну для правильного переміщення й видалення у v-for.
14. **Чому оновлюються обидві сторінки?** Вони імпортують один реактивний taskState з модуля сховища.
15. **Чому дані повертаються після перезавантаження?** Стан у пам’яті створюється заново з демонстраційних даних, постійне сховище відсутнє.
16. **Для чого Pinia та IndexedDB?** Pinia впорядкує управління станом, actions і getters; IndexedDB забезпечить постійне локальне зберігання структурованих даних та роботу з ними офлайн. Pinia сама по собі не зберігає стан після перезавантаження.

## Висновок

У ході роботи вдосконалив управління списком TaskFlow: створив керований компонент пошуку та фільтрів, комбіновані умови, сортування без мутації спільного порядку й підтверджене видалення. Виконав усі шість додаткових завдань і зберіг можливості попередніх робіт. Автоматичні перевірки та production-збірка пройшли. Поточне обмеження — стан існує лише протягом сеансу; для завершення звіту потрібні актуальні скріншоти та браузерна перевірка.
