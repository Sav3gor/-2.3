# Звіт із практичної роботи КП 2.5

## Тема та мета

**Тема:** Розробка компонентів Vue у PWA-застосунку TaskFlow. Картки завдань, індикатори статусу, пріоритети, Props та Emits.

**Мета:** навчитися створювати повторно використовувані компоненти Vue 3, передавати дані через Props, генерувати події Emits, застосовувати реактивність і розробляти компонентний інтерфейс.

## Теоретичні відомості

Компонент Vue об’єднує шаблон, логіку та стилі незалежної частини інтерфейсу. Single File Component має розширення `.vue`. У `<script setup>` доступні макроси `defineProps()` для вхідних властивостей і `defineEmits()` для подій компонента.

Props передають дані від батьківського компонента до дочірнього. Дочірній компонент повідомляє про дію користувача через Emits із payload. Дані змінює батьківський обробник через функції сховища. `ref()` зберігає реактивне значення, `reactive()` створює реактивний об’єкт, `computed()` обчислює похідні значення та оновлює їх при зміні залежностей.

## Реалізація

`data/tasks.js` містить шість базових і чотири додаткові завдання. Кожне має `id`, `title`, `description`, `status`, `priority`, `dueDate`. Додаткові завдання стосуються перевірки PWA без мережі, звіту, іконок та доступності.

`store/tasks.js` створює спільний реактивний стан із копій початкових записів. `setTaskStatus()` та `setTaskPriority()` перевіряють допустимі значення і знаходять запис за `id`. Некоректне значення або відсутній запис не змінюють стан.

`StatusBadge` показує «Заплановано», «У роботі», «Виконано» з різними кольорами. Для невідомого значення показує «Невідомо». `PriorityBadge` показує «Низький», «Середній», «Високий» або «Не визначено».

`TaskCard` відображає назву, опис, індикатори, термін українською мовою та кнопки. Статус змінюється циклом `todo → progress → done → todo`, пріоритет — `low → medium → high → low`. Компонент не змінює отримане завдання. Натискання назви генерує `task-select`; батьківська сторінка відкриває панель із вибраним завданням.

Приклад Props та Emits з реалізації:

```js
const props = defineProps({ task: { type: Object, required: true } })
const emit = defineEmits(['status-change', 'priority-change', 'task-select'])

function changeStatus() {
  const index = statusSequence.indexOf(props.task.status)
  emit('status-change', {
    id: props.task.id,
    status: statusSequence[(index + 1) % statusSequence.length],
  })
}
```

Приклад у батьківській сторінці:

```vue
<TaskCard v-for="task in filteredTasks" :key="task.id" :task="task"
  @task-select="handleTaskSelect"
  @status-change="handleStatusChange"
  @priority-change="handlePriorityChange" />
```

`HomePage` обчислює загальну кількість, кількість запланованих, поточних і виконаних завдань, відсоток виконання, три актуальні записи з найвищим пріоритетом. `TasksPage` поєднує фільтри через логічне AND, показує кількість результатів через `TaskCounter` і підтримує сортування в обох напрямках.

## Результати додаткових завдань

1. Додано чотири власні завдання № 7–10 з різними статусами та пріоритетами.
2. Додано статистику «Заплановано».
3. Створено `TaskCounter.vue` з числовим Props `count`.
4. Виводиться відсоток виконання з елементом `progress`; для порожнього набору результат дорівнює 0%.
5. Реалізовано `task-select` з payload `{ id }`, обробку на обох сторінках і панель обраного завдання.
6. Реалізовано сортування від високого та від низького пріоритету, а також відновлення початкового порядку.

Для десяти записів початкова статистика: **усього — 10, у роботі — 3, виконано — 3, заплановано — 4; виконання — 30%**. Значення 6 / 2 / 2 із методички стосуються лише базових шести записів до виконання додаткових завдань.

## Перевірка

Дата: 17 листопада 2026 року.

- `npm run build` — успішно; створено production-ресурси, manifest і service worker. Vite повідомляє про великий JS-бандл Framework7.
- `npm test` — перевірено допустимі та некоректні зміни стану, відсутній id, payload подій, незмінність Props, невідомі значення індикаторів, початкові показники статистики, комбіновані фільтри, порожню вибірку, сортування, панель обраного завдання й реактивне оновлення обох сторінок.
- Сценарій «У роботі» + «Високий» залишає один запис № 3 «Створити індикатор статусу». Після «Завершити» список порожній, статистика стає 10 / 2 / 4 / 4, виконання — 40%.
- Тести монтують справжні Vue-компоненти у тестовий renderer; оболонки Framework7 підмінені. Браузерну навігацію, адаптивність і офлайн-режим ці тести не перевіряють.

## Скріншоти та браузерна перевірка — потрібно завершити

Справжні скріншоти поки не отримано: локальний сервер не запускається через `listen EPERM`, Firefox завершується помилкою `snap-confine`. Наведені нижче пункти є інструкцією для завершення звіту, а не свідченням проведеної браузерної перевірки.

1. Запустити `npm run dev` у `my-app`, відкрити адресу Vite. Зняти головну сторінку зі статистикою 10 / 3 / 3 / 4 та 30%.
2. Перейти через Tabbar до «Завдання». Зняти сторінку з фільтрами й лічильником 10.
3. Вибрати «У роботі» та «Високий». Зняти картку № 3 перед зміною: «У роботі», «Високий».
4. Натиснути «Завершити», переконатися в порожній вибірці. Вибрати статус «Виконано», залишивши «Високий», знайти картку № 3 та натиснути «Змінити пріоритет». Вибрати пріоритет «Низький» і зняти картку після зміни: «Виконано», «Низький».
5. Повернутися на головну: має бути 10 / 2 / 4 / 4 та 40%. Перезавантажити браузер: повернуться початкові дані.
6. Перевірити Tabbar, сторінку «Про застосунок», вигляд при ширині 360 px і 1280 px. Перевірити PWA на production-збірці через `npm run preview`: після першого онлайн-відвідування та активації service worker повторно відкрити застосунок без мережі.

## Відповіді на контрольні запитання

1. **Компонент Vue 3** — повторно використовувана частина інтерфейсу зі своєю логікою та шаблоном. Компонентний підхід зменшує дублювання, спрощує підтримку та ізолює відповідальність.
2. **v-for** створює елементи або компоненти для кожного запису колекції.
3. **:key** задає стабільну унікальну ідентичність запису, щоб Vue коректно оновлював, переміщував і видаляв елементи.
4. **Props** — вхідні дані компонента, передані батьківським компонентом.
5. **defineProps()** оголошує вхідні властивості, їх типи, обов’язковість і значення за замовчуванням.
6. **Emits** — власні події компонента; **defineEmits()** оголошує їх і повертає функцію надсилання подій.
7. Дочірній компонент не повинен змінювати Props, бо джерелом даних керує батьківський компонент. Зміна через подію забезпечує зрозумілий потік даних.
8. **ref()** обгортає значення, доступне через `.value` у JavaScript; **reactive()** повертає Proxy об’єкта. У шаблоні ref зазвичай розгортається автоматично.
9. **computed()** створює кешоване похідне значення, яке перераховується при зміні реактивних залежностей.
10. Обидві сторінки імпортують один екземпляр `taskState` із модуля сховища; Vue відстежує його зміни.
11. Картка визначає наступний статус і генерує `status-change` з `{ id, status }`. Батьківський обробник викликає `setTaskStatus()`, після чого інтерфейс реактивно оновлюється.
12. Окремі індикатори забезпечують повторне використання та однакові підписи й кольори в усіх місцях.
13. Payload передається другим аргументом: `emit('status-change', { id: 1, status: 'done' })`.
14. Після повного перезавантаження стан у пам’яті створюється заново з демонстраційних даних; постійне сховище в цій роботі не використовується.
15. Потрібно імпортувати `TaskCard`, передати `:task` і підписатися на `status-change`, `priority-change`, за потреби `task-select`.

## Висновки

Реалізовано компонентний інтерфейс TaskFlow з Props, Emits, спільним реактивним станом та обчислюваними показниками. Практично застосовано відокремлення даних від подання, повторне використання компонентів, комбіновану фільтрацію та сортування. Збірка й автоматизована перевірка логіки пройшли. Для остаточного оформлення звіту залишаються справжні скріншоти та браузерна перевірка в середовищі, де доступний запуск сервера й браузера.
