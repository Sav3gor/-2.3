# Звіт із практичної роботи КП 2.6

## Тема, мета та функціональні зміни

**Тема:** реактивні форми, створення та редагування завдань у PWA-застосунку TaskFlow.

**Мета:** навчитися створювати реактивні поля введення у Vue 3, застосовувати v-model, перевіряти дані користувача, передавати результати через Props та Emits й оновлювати спільний стан застосунку.

Роботу виконано в наявному проєкті TaskFlow на Vue 3, Framework7 і Vite. До сторінки «Мої завдання» додано універсальну форму створення та редагування, повідомлення про помилки, попередній перегляд і пошук за назвою. Навігація, PWA, статистика, фільтри, сортування, TaskCounter та вибір завдання з КП 2.5 збережені. Вихідні дані, маршрути, App.vue, main.js, AppTabbar, StatusBadge і PriorityBadge не змінено.

## Теоретичні відомості

**Реактивність** забезпечує автоматичне оновлення інтерфейсу при зміні даних. ref() створює реактивне значення з доступом через .value у JavaScript. reactive() повертає реактивний об’єкт; він зручний для кількох полів однієї форми. computed() обчислює похідне значення й перераховує його при зміні залежностей.

**v-model** синхронізує значення input, textarea або select із реактивним полем. Модифікатор .trim прибирає крайні пробіли. Обробник @submit.prevent запускає збереження без стандартного перезавантаження сторінки. Атрибут novalidate дозволяє показувати власні узгоджені повідомлення українською мовою.

**Props** передають у форму редаговане завдання та список записів для перевірки унікальності. **Emits** повідомляють батьківську сторінку про save або cancel. TaskForm працює з локальною копією полів, тому введення й скасування не змінюють оригінал. Додаткова валідація у сховищі захищає дані, навіть якщо функції викликають без форми.

## Розширення реактивного сховища

**addTask(data)** перевіряє поля, прибирає крайні пробіли, обчислює ID як максимальний поточний ID + 1, додає запис і повертає його. За помилки повертає null і не змінює список.

**updateTask(data)** знаходить запис за ID, перевіряє нові значення та оновлює знайдений об’єкт через Object.assign(). ID і кількість записів зберігаються. Для відсутнього запису або некоректних даних повертається null.

```js
const nextId = taskState.tasks.reduce(
  (maxId, task) => Math.max(maxId, task.id), 0,
) + 1
const newTask = { id: nextId, ...normalized }
taskState.tasks.push(newTask)
```

Стан зберігається лише в оперативній пам’яті. Постійне сховище не додавалося. Десять демонстраційних завдань КП 2.5 збережені; категорія «Навчання» підставляється у сховищі, без зміни src/data/tasks.js.

## Компонент форми та валідація

**TaskForm.vue** отримує task=null для створення або об’єкт task для редагування. Локальна форма має назву, опис, статус, пріоритет, категорію й дату завершення. Кожне поле має підпис; обов’язкові поля позначено зірочкою та атрибутом required.

```vue
<form novalidate @submit.prevent="submitForm">
  <input v-model.trim="form.title" type="text" maxlength="80" />
  <textarea v-model.trim="form.description" maxlength="300"></textarea>
  <select v-model="form.status">...</select>
</form>
```

Об’єкт errors обчислюється реактивно. Помилки з’являються після першої спроби збереження й далі оновлюються під час введення. До повідомлень ведуть aria-describedby; некоректні поля мають aria-invalid, а після невдалого submit фокус переходить на перше з них.

```js
const errors = computed(() => validateTask(form, {
  originalTask: props.task,
  tasks: props.tasks,
}))
```

**submitForm()** вмикає показ помилок і зупиняє збереження, якщо вони є. Інакше генерує save з копією полів та очищеними від крайніх пробілів назвою й описом.

Правила: назва — 3–80 символів після trim, опис — до 300 символів; статус, пріоритет і категорія — лише з дозволених списків. Дата є обов’язковою, перевіряється формат і реальна календарна дата, включно з високосними роками. Нове завдання не може мати минулий термін. При редагуванні дозволено залишити початкову минулу дату, проте новий термін має бути сьогоднішнім або майбутнім. Назва нового завдання має бути унікальною без урахування регістру й крайніх пробілів.

Попередній перегляд оновлює назву, опис, статус, пріоритет, категорію й термін без натискання кнопок. Кнопка «Очистити форму» доступна під час створення та повертає стандартні значення. «Скасувати» і «Закрити» закривають форму без запису в сховище.

## Інтеграція зі сторінкою та карткою

TaskCard отримує Boolean Props editable. Кнопка «Редагувати» відображається лише у вкладці завдань і генерує edit з ID. На головній сторінці ця кнопка відсутня. У картці додатково відображається категорія; події зміни статусу, пріоритету та task-select з попередньої роботи збережені.

**saveTask(data)** у TasksPage вибирає addTask() або updateTask() залежно від editingId. Після успіху показує підтвердження, закриває форму й скидає фільтри статусу, пріоритету та пошуковий запит. За помилки форма залишається відкритою, виводиться повідомлення.

```vue
<TaskForm :key="editingId ?? 'new'"
  :task="editingTask" :tasks="taskState.tasks"
  @save="saveTask" @cancel="cancelForm" />
```

Завдяки key при переході між різними завданнями створюється новий локальний стан форми. Сторінки HomePage і TasksPage використовують спільний taskState, тому зміни записів одразу впливають на картки, фільтри, кількість завдань і відсоток виконання.

## Додаткові завдання

1. Додано категорії «Навчання», «Робота», «Особисте»: вибір у формі, збереження у стані, показ у картці та preview.
2. Реалізовано перевірку минулої дати; під час редагування старий термін можна залишити без змін.
3. Показується кількість символів, що залишилися для назви й опису.
4. Кнопка «Очистити форму» повертає стандартні значення режиму створення та приховує попередні помилки.
5. Обов’язкові поля візуально позначено, додано required, aria-invalid, aria-describedby, повідомлення role=alert і керування фокусом.
6. Реалізовано реактивний пошук за назвою без окремої кнопки, без урахування регістру та крайніх пробілів. Він поєднується з фільтрами й сортуванням.
7. У формі й сховищі перевіряється унікальність назви нового завдання.

## Результати перевірки T1–T8

Перевірка виконується командою npm test. Справжні Vue-компоненти монтуються у тестовий renderer, оболонки Framework7 підмінено. Перевірки охоплюють події, реактивність і стан; візуальний вигляд та браузерні переходи потребують окремої перевірки.

| T3 | Заповнення коректних полів і створення | Preview оновлено, додано ID 11, список збільшився з 10 до 11 | Пройдено |

| T5 | Зміна назви й натискання «Скасувати» | Початковий об’єкт не змінився; повторне відкриття показало вихідну назву | Пройдено |

У T8 виконано повторне завантаження модуля з незалежним станом. Фактичне натискання F5 у браузері не перевірялося. Очікувані 6 записів з методички замінено на 10, оскільки в попередній роботі виконано додаткове завдання з чотирма власними записами.

Додатково перевірено: некоректні дати 29 лютого невисокосного року, 30 лютого й 31 квітня; минулий термін; граничні довжини; дублікати назви в іншому регістрі; невідомі значення списків; відсутній ID; очищення форми; категорії; пошук; збереження функцій КП 2.5.

Production-збірка npm run build успішна: сформовано dist, manifest і service worker. Попередження Vite про JS-чанк понад 500 kB не перешкоджає збірці.

## Контрольні запитання

1. **Що означає реактивність у Vue 3?** Це автоматичне відстеження змін стану та оновлення залежних частин інтерфейсу.
2. **У чому різниця між ref() і reactive()?** ref() обгортає значення, доступне через .value у JavaScript; reactive() повертає Proxy об’єкта з реактивними властивостями.
3. **Для чого застосовується v-model?** Для двосторонньої синхронізації значення поля введення й реактивного стану.
4. **Що робить v-model.trim?** Прибирає пробіли на початку й наприкінці введеного тексту.
5. **Яку роль виконує computed() під час валідації?** Реактивно формує об’єкт помилок і перераховує його при зміні полів.
6. **Навіщо @submit.prevent?** Щоб обробити submit у JavaScript без стандартного надсилання форми та перезавантаження сторінки.
7. **Навіщо novalidate?** Щоб використовувати власні повідомлення про помилки українською мовою замість стандартних підказок браузера.
8. **Навіщо локальна копія редагованих даних?** Щоб введення не змінювало сховище до підтвердження, а скасування залишало оригінал незмінним.
9. **Які події генерує TaskForm?** save передає перевірені поля у saveTask(), cancel закриває форму через cancelForm().
10. **Чим створення відрізняється від редагування?** Створення додає новий запис із новим ID; редагування оновлює наявний запис, зберігаючи його ID.
11. **Як формується ID?** Як максимальний ID серед поточних завдань плюс один; для порожнього списку перший ID дорівнює 1.
12. **Навіщо перевірка у store/tasks.js?** Щоб некоректні дані не потрапляли у спільний стан при викликах addTask() або updateTask() поза формою.
13. **Чому після створення змінюється статистика?** HomePage обчислює показники через computed() зі спільного реактивного taskState.tasks.
14. **Чому «Скасувати» не повинна змінювати оригінал?** Користувач відмовляється від правок; тому форма лише закривається, а локальна копія відкидається.
15. **Що станеться після оновлення браузера?** Додані та відредаговані записи зникнуть, оскільки стан заново створиться з src/data/tasks.js; постійне зберігання в цій роботі не реалізується.

## Висновок

У ході роботи розширив TaskFlow створенням і редагуванням завдань. Застосував reactive(), ref(), computed(), v-model, Props та Emits, реалізував спільну валідацію у формі й сховищі, попередній перегляд, скасування без зміни оригіналу та реактивне оновлення статистики. Виконав усі сім додаткових завдань. Автоматизовані перевірки логіки та production-збірка пройшли; для остаточного оформлення звіту залишаються справжні скріншоти й браузерна перевірка.
