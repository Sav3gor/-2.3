# TaskFlow — практичні роботи КП 2.5–2.6

PWA на Vue 3, Vite та Framework7. Наявні маршрути `/`, `/tasks/`, `/about/`, AppTabbar і реєстрацію Framework7 збережено.

## Запуск

```bash
cd '/home/egor/КПП 2.2/my-app'
npm ci
npm run dev
```

## Перевірка

```bash
npm test
npm run build
npm run preview
```

Тести використовують `node:module.registerHooks` (Node.js ≥ 22.15 або ≥ 23.5); перевірено на Node.js 26.13.1. Vue-компоненти монтуються у тестовому renderer з підміною оболонок Framework7. Це перевірка логіки та реактивності, а візуальний вигляд і навігацію слід перевіряти в браузері.

## Можливості

- Картки з українською датою, статусом і пріоритетом; зміни через Props/Emits.
- Цикли статусів `todo → progress → done → todo` і пріоритетів `low → medium → high → low`.
- Спільне реактивне сховище з перевіркою допустимих значень.
- Сумісні фільтри статусу та пріоритету, лічильник і порожній стан.
- Сортування від високого або низького пріоритету та початковий порядок.
- Чотири показники статистики, відсоток виконання і три актуальні завдання.
- Подія `task-select` при натисканні назви; панель обраного завдання на обох сторінках.
- Адаптивна сітка і доступні кнопки фільтрів.

Виконано всі шість додаткових завдань. Додані записи № 7–10: початкова статистика **10 / 3 / 3 / 4**, виконано **30%**. Шість базових записів залишено відповідно до PDF. Стан зберігається в пам’яті; перезавантаження відновлює демонстраційні дані.

Звіт і відповіді на контрольні запитання: [../docs/report-kp-2-5.md](../docs/report-kp-2-5.md). У звіті зазначено обмеження перевірки й перелік потрібних скріншотів.

## КП 2.6 — реактивні форми

Додано створення та редагування через TaskForm, двостороннє зв’язування v-model,
спільну валідацію форми й сховища, preview, повідомлення про результат і скасування
без зміни оригіналу. ID нового запису — максимальний поточний ID + 1.

Виконано всі 7 додаткових завдань: категорії, дата не в минулому, залишок символів,
очищення форми, доступні підписи й помилки, реактивний пошук, унікальна назва нового
завдання без урахування регістру. Під час редагування старий термін дозволено залишити,
але нова дата має бути не раніше сьогодні. Категорія початкових завдань — «Навчання»;
файл початкових даних не змінено. Після перезавантаження стан відновлюється.

`npm test` перевіряє сценарії T1–T7, повторну ініціалізацію сховища для T8,
додаткові правила та збереження функцій КП 2.5. Браузерне натискання F5 і вигляд
інтерфейсу потребують окремої перевірки.

Звіт: [../docs/report-kp-2-6.md](../docs/report-kp-2-6.md).

Публікація на чинний Worker `2-3` з кореня репозиторію:

```bash
npm run build --prefix my-app
npx wrangler deploy --message "Complete KP 2-6 TaskFlow"
```

## КП 2.8 — управління списком

У вкладці «Завдання» компонент TaskListControls забезпечує пошук **у назві й описі**,
фільтри статусу та пріоритету, швидкий фільтр невиконаних і скидання умов.
Додано сортування за назвою, пріоритетами, датами в обох напрямках, статусами та ID.
Сортується похідний масив; порядок у спільному стані зберігається.

Кнопка «Видалити» запитує підтвердження з назвою завдання. Видалення оновлює
обидві сторінки й закриває форму/панель вибраного запису. Є окремі стани порожньої
вибірки та повністю порожнього списку. Виконано всі 6 додаткових завдань, включно
з відсотком виконання у вибірці та очищенням лише тексту пошуку.

За новими вимогами опис дозволено до **500 символів**, термін — **необов’язковий**.
Записи без дати залишаються в кінці при обох напрямках сортування термінів.
Ці правила замінюють обмеження 300 символів та обов’язкову дату з КП 2.6.
Категорії, інші перевірки та можливості попередніх робіт збережено.

`npm test`: 12 автоматичних перевірок зі сценаріями 01–14 та попередніми можливостями.
Тести використовують тестовий renderer і підміну window.confirm; браузерну
перевірку та справжні скріншоти потрібно виконати окремо.

Звіт: [../docs/report-kp-2-8.md](../docs/report-kp-2-8.md).

```bash
npm run build --prefix my-app
npx wrangler deploy --message "Complete KP 2-8 TaskFlow"
```

## КП 2.9 — Pinia та проєкти

Код перенесено на useTasksStore та useProjectsStore. Завдання, проєкти, умови списку
та getters статистики належать Pinia; стан форми залишається локальним.
Додано створення проєктів, прив’язку, фільтр, статистику на обох сторінках,
групове переведення проєкту в роботу з підтвердженням і «Лише без терміну».
Категорії та можливості КП 2.8 збережено. Постійне збереження не реалізується.

Спочатку встановіть залежності з каталогу my-app:

```bash
npm install pinia @vue/devtools-api
npm test
npm run build
```

Встановлено pinia 4.1.0 та @vue/devtools-api 8.2.1. Усі **16 автоматичних перевірок**
та production-збірка проходять. Тести використовують справжню Pinia й тестовий Vue
renderer; оболонки Framework7 та window.confirm підмінені. Візуальний вигляд,
реальну навігацію й Devtools потрібно перевірити в браузері та додати скріншоти.
Додаткові функціональні пункти 1–5 реалізовано; пункт 6 з перевіркою через
Vue Devtools залишається для браузерної перевірки.

Звіт: [../docs/report-kp-2-9.md](../docs/report-kp-2-9.md).

Публікація КП 2.9 із кореня репозиторію на чинний Worker `2-3`:

```bash
npm run build --prefix my-app
npx wrangler deploy --message "Complete KP 2-9 TaskFlow"
```
